# How this repo is put together

The site is **hosted on Vercel** at www.dxbdubaicreekharbour.ae; the bare
domain dxbdubaicreekharbour.ae redirects there (308). `SITE.url` must stay the
www address: canonicals, the sitemap, `robots.txt`, share previews and the
structured data are all built from it, and Google will not index a sitemap
URL that redirects (Search Console's "Page with redirect" / "Redirect error",
October 2026). If the primary domain in Vercel is ever changed, change
`SITE.url` (in the generator too) and re-run `npm run sitemap` in the same
deploy. Vercel deploys
whatever is on `main` in this repo. Since October 2026 the code is edited
**here, in this repo** — the Lovable project "Creek Harbour Showcase" was the
starting point but is now behind this repo and should not be copied over it.

## Where things live

- `src/data/projects.ts` — the 42 projects: every price, size, unit count,
  payment schedule, handover date, amenity and image caption. **Generated**
  from Emaar's own pages by the snapshot tooling (see "Refreshing the data");
  never hand-edit a figure.
- `src/data/transactions.json` — registered sales and tenancy contracts for
  Dubai Creek Harbour: Dubai Land Department registration records, obtained
  through the PropertyIndex data service (the site credits the Dubai Land
  Department and names no supplier; PropertyIndex appears only here and in
  the generators). Also generated; `src/data/transactions.ts` types it and
  adds the per-project helpers. Shown as registered, never as valuations.
- `src/data/legal.ts` — the Terms of Use and Privacy Notice as structured
  sections (`/terms`, `/privacy`); the `{{company}}`, `{{licence}}`,
  `{{broker}}`, `{{address}}` and `{{noc}}` tokens are filled from `SITE` in
  `projects.ts` (set in the generator): Felicity Properties L.L.C, RERA ORN
  33951, BRN 59244, trade licence 1145910, the Business Bay office and the
  Emaar no-objection certificate of 24 December 2024. Licence, ORN and broker
  card all expire 7 February 2027 — update `SITE` if the numbers change on
  renewal. `SITE.dldPermit` (Trakheesi advertising permit) is still empty.
- `src/data/benefits.ts` — the "Why Dubai Creek Harbour" cards; every card
  cites an Emaar page or the DLD snapshot, with the exact quotes kept in
  `design/benefits-sources.json`.
- `public/sw.js` + `public/site.webmanifest` — the site installs on phones
  like an app (standalone display, home-screen icon). Pages are always
  fetched from the network first; only images and hashed build assets are
  cached. Bump `VERSION` in `sw.js` to clear old caches.
- `public/img/<project-slug>/` — Emaar's renders and photos, resized to
  480/960/1600 WebP plus a 1200×630 `og.jpg` for sharing previews.
  `public/img/district/` holds the area images.
- `src/routes/` — `index.tsx` (home), `projects.index.tsx` (`/projects`, all
  projects with filters), `projects.$slug.tsx`, `payment-plans.tsx` (every
  published schedule), `market.tsx` (registered sales and rents), `area.tsx`
  (the district), `guide.tsx` (buying steps, costs, FAQ), `terms.tsx`,
  `privacy.tsx`, `leads.tsx` (private enquiries page).
- `src/lib/seo.ts` — title/description length rules, project titles and
  descriptions, the brokerage's structured data (Felicity Properties, RERA
  ORN, BRN, trade licence) and breadcrumbs.
- `public/sitemap.xml` and `public/robots.txt` — generated by `npm run sitemap`
  (`scripts/sitemap.mjs`) from the data files and `SITE.url`; re-run it after
  adding a page or refreshing data. A test fails if either names an address
  other than `SITE.url`.
- `public/fonts/` — Inter and Cormorant Garamond, self-hosted (SIL Open Font
  License), so no page loads anything from Google.
- `SITE.googleSiteVerification` in the generator — paste the Search Console
  "HTML tag" code there (or verify by DNS instead) and regenerate.
- `src/components/showcase/` — header, footer, cards, gallery, shared helpers
  and the exact footer disclaimer. `src/components/market/` — the
  transaction tables and summaries. `src/components/enquiry/` — the form.
- `src/lib/enquiries.functions.ts` — server side of the form and `/leads`.
  Enquiries go to the Neon database Vercel provides as `DATABASE_URL`; the
  `enquiries` table creates itself (and adds new columns) on first use.
- FelicityBot, the AI assistant (button bottom right, every page except
  `/leads`): `src/components/felicitybot/FelicityBot.tsx` is the chat panel;
  `src/lib/felicitybot.functions.ts` calls the Claude API; and
  `src/lib/felicitybot.knowledge.ts` holds its rules plus the knowledge it
  answers from, rendered from `projects.ts`, `transactions.json`, the guide,
  FAQ, benefits and district text. It has no other source, so refreshing
  the data refreshes the bot. When a visitor asks to be contacted and agrees,
  it saves an enquiry through the same code as the form (marked
  "[Via FelicityBot]" on `/leads`). Conversations stay in the visitor's
  browser tab; nothing is stored unless they ask to be contacted. Each
  reply is signed, so the browser can't pass off made-up bot turns.
  Question counts live in the `site_counters` table: per visitor per day
  (keyed by a scrambled code made from the IP address, not the address),
  and for the whole site per hour and per day. It creates itself; rows
  older than three days are deleted at the start of each hour the bot is
  used and whenever `/leads` is opened. A question turned away by one limit
  doesn't count against the next, so one visitor can't use up the site's
  allowance.

## Refreshing the data

Both data files carry the date they were taken. To refresh:

1. Re-run the Emaar extraction and `build.py` to regenerate
   `src/data/projects.ts` (prices, unit counts, sizes, schedules, status).
2. Re-query PropertyIndex and run `build_transactions.py` to regenerate
   `src/data/transactions.json`.
3. Build, check every page, commit, push.

The generators live with the session tooling, not in this repo; the rule
that matters is in `AGENTS.md`: no Dubai real-estate figure is ever typed in
by hand.

## Vercel settings

- `vercel.json` tells Vercel how to install and build (npm, not bun: Lovable's
  `bun.lock` points at Lovable's private package registry).
- Environment variables:
  - `DATABASE_URL` — from the Neon integration. Enquiries are saved here.
  - `LEADS_PASSWORD` — password for `/leads`, **at least 20 characters**
    (shorter ones are refused, because nothing slows down guessing). Set it
    before the last deployment or redeploy after setting it.
  - `RESEND_API_KEY` — optional. When set, every new enquiry is also emailed
    to `LEAD_EMAIL` (default: the address in `SITE.email`,
    mouhannad@felicitypro.com) through Resend. The sender is `LEAD_FROM`,
    default `DXB Creek Harbour <enquiries@felicitypro.com>`, which works once
    felicitypro.com is verified in Resend (Domains → Add domain → paste the
    DNS records it gives at felicitypro.com's DNS host). Until then Resend
    refuses that sender and the code falls back to Resend's test sender,
    which only delivers to the email the Resend account was opened with — so
    open the Resend account with mouhannad@felicitypro.com. Without the key,
    enquiries are only saved to the database and shown on `/leads`.
  - `ANTHROPIC_API_KEY` — switches FelicityBot on. Create it at
    console.anthropic.com (Settings → API keys) and set a monthly spend
    limit there (Settings → Limits): that limit is the real cost ceiling.
    Without the key the chat panel offers WhatsApp instead of answering.
  - `FELICITYBOT_MODEL` — optional. Default `claude-opus-5-5` (best at
    sticking to the "only quote the site's figures" rule; $4 / $20 per
    million input / output tokens, $0.20 for cached input). Set
    `claude-haiku-5-5` for a much cheaper bot ($0.10 / $0.50). The rules
    and knowledge (about 100,000 characters) are sent with every question
    and cached for five minutes, so a visitor's follow-up questions mostly
    read the cache. Actual spend shows under Usage in the Anthropic console.
  - `FELICITYBOT_HOURLY_LIMIT` / `FELICITYBOT_DAILY_LIMIT` — optional, default
    400 and 2,000 questions for the whole site (UTC hours and days);
    `FELICITYBOT_VISITOR_DAILY_LIMIT`, default 150 per visitor per day. Past
    any of these the bot tells the visitor to use WhatsApp. A separate burst
    brake (30 questions per 10 minutes from one connection, per server)
    asks the visitor to try again later. The daily cap times the cost of a
    question bounds a normal bad day; if the database is unreachable the
    caps are skipped, so the monthly limit in the Anthropic console is the
    only hard ceiling.
  - The bot's answers may take up to 60 seconds: `vite.config.ts` sets the
    function's `maxDuration` to 60, the most every Vercel plan allows. The
    bot keeps its own deadline (45 s for model calls, and a lead is only
    saved with time left to confirm it) inside that.
- Visitor numbers: the site's own, shown on `/leads` (Visitors tab) behind
  `LEADS_PASSWORD`; nothing to switch on. `src/components/SiteAnalytics.tsx`
  keeps one visit per browser tab (sessionStorage, no cookies: pages opened,
  seconds on screen and in use) and reports it to `POST /api/visit`
  (`src/routes/api.visit.ts` → `src/lib/visits.server.ts`) when the visitor
  leaves or switches away. One row per visit in `site_visits` (creates
  itself; rows older than 13 months are deleted), so the database is woken
  about once per visit, never per page. No IP address is stored: "visitor"
  is a code from IP + browser that changes daily. `/leads` reads it through
  `getVisitStats` (`src/lib/visits.functions.ts`).
  - The owner's own visits: typing the password on `/leads`, or opening
    `/leads?me=1`, marks that browser ("dxbch-dont-count") and it sends
    nothing; `/leads` itself is never counted.
  - Neon's free plan pauses the database for the rest of the month if its
    compute allowance runs out (about 100 CU-hours: roughly 13 hours a day
    awake at the smallest size; every write keeps it awake 5 minutes). So
    enquiries no longer depend on the database alone: if the insert fails or
    takes over 5 s, the lead email still goes out (marked "not on the /leads
    page") and the visitor sees success. /leads warns when lead emails
    aren't set up, and when the site averages more than 120 visits a day:
    then create a second free Neon project and set `ANALYTICS_DATABASE_URL`
    to it, so visit numbers can never use up the enquiries' allowance.
  - Comparisons ("▲ 12% on the 7 days before") use the same stretch of time
    cut at the same clock time, and only once counting covered it.
    "Visitors" over several days adds up each day's visitors. Referring
    sites or campaign tags from fewer than two visitors in the period are
    grouped as "Other sites". The visitor code's key is derived with scrypt
    from `ANALYTICS_SECRET` (or `LEADS_PASSWORD`).
  - Vercel Web Analytics is no longer used; it can be switched off in the
    project's Analytics tab.
- Node.js 22.x (set in `package.json` → `engines`).
- Both the domain and the two variables must be on the same Vercel project.

## Checking a change locally

`npm install --include=dev --legacy-peer-deps`, then
`NITRO_PRESET=node-server npm run build` and
`PORT=4700 node .output/server/index.mjs`. `npx tsc --noEmit` and
`npm test` must pass before pushing.

## Rules the content follows

- Independent showcase, not Emaar's site; the footer disclaimer says so on
  every page and names the two data sources and their dates.
- Emaar figures come only from `src/data/projects.ts`; registered figures
  only from `src/data/transactions.json`. Don't add numbers anywhere else —
  that includes FelicityBot's rules text.
- Photos and brochures are Emaar's official files; brochures and floor plans
  link to Emaar's site, images are self-hosted copies with Emaar credited in
  every caption.
